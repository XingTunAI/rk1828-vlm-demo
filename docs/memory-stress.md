# VLM 内存边界与高负载稳定性测试

目标是确定最高稳定负载、首次失败条件，以及失败后恢复能力。内存占用达到 100% 不是通过标准。本方案尚未完成实机执行。

## 分开记录两类内存

- RK1828：使用 `rknn-smi info` 记录加速器内存、健康状态、温度和利用率。本次设备报告总计 5120 MB。
- RK3588 Host：记录 `/proc/meminfo` 的 MemAvailable，以及推理进程 RSS、退出状态和内核 OOM 日志。Host 内存不能代表加速器内存。

SMI 由单个采集流程串行调用，避免与其他监控工具并发采集。初期每 5 秒采样，注明该间隔可能漏掉瞬时峰值。测试与采样使用同一时间基准，关联请求记录。

开发电脑已可执行以下独立采样工具（需要 Node.js 与 ADB）。默认采样 60 秒，最多 8 小时，Ctrl+C 停止；多个设备用 `ANDROID_SERIAL` 指定。不要同时启动多个采样器。

```bash
node scripts/sample-memory.mjs 60
```

结果写入 `results/memory-<时间戳>/samples.jsonl`，包含 RK1828 总内存/空闲内存、Host 总内存/可用内存、采样耗时和原始输出。该脚本已通过实机空闲采样验证；尚不包含进程 RSS、温度趋势或自动负载控制。

## 测试阶段

| 阶段 | 操作 | 观察 |
| --- | --- | --- |
| 基线 | 单 session、固定图片与短提示词 | 正确回答、首内容延迟、生成速度、内存基线 |
| 上下文扫描 | 在转换上限内增加实际输入及输出预算 | 加载占用、推理峰值、截断、延迟 |
| 会话扫描 | 独立运行配置逐档增加服务端 session；请求独占 slot | 内存、成功率、吞吐、首次失败档位 |
| 视觉负载 | 使用匹配转换配置的不同图像分辨率或视觉 token 配置 | 视觉内存峰值和首内容延迟 |
| 高负载长稳 | 选择已验证成功的最高负载附近，先 30 分钟，再 2/8 小时 | 内存持续增长、性能下降、退出、失联 |
| 边界后恢复 | 停止升档、排空在途请求，再执行基线请求 | 是否恢复，是否需要重启服务，设备是否仍健康 |

每次只改变一个维度。服务端可能提前分配 KV cache：增大提示词长度不一定增加已分配内存，需结合上下文和 session 启动配置实测。增加 HTTP 并发也不必然增加设备端并行度。

固定尺寸视觉模型通常会缩放输入图片；仅上传更大的原始 JPEG 不能证明增加了 NPU 视觉负载。当前网页仅支持单图及固定图片循环，分辨率切换、多图和自动服务配置扫描仍待实现。

## 失败分类与停止条件

内存不足或模型加载失败、请求超时、流中断、推理服务崩溃、Host OOM、设备失联分别记录。出现首个明确资源不足或设备健康异常时停止升档，保存日志；不要自动重试掩盖失败，也不要自动重置设备。

负载解除后执行短图片问答检查恢复。若需要重启服务，应单独记录为人工恢复，不能当作连续稳定运行。

## 报告要求

报告绑定模型文件哈希、量化、图像输入配置、上下文、session 数、实际并发、SDK/固件、测试时长及采样间隔。记录基线与峰值内存、可用内存、成功率、延迟趋势、失败原因和恢复耗时。

同时报告最高稳定档位和首次失败档位。内存增长需在相同负载下重复观察，区分缓存保留、内存池与泄漏；不能仅凭一次高占用判断泄漏。
