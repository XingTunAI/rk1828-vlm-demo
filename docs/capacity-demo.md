# RK1828 复核能力 Demo

只向 RK1828 的 VLM 服务发请求，模拟上游送图；不依赖 1684X。

## 页面操作

1. 运行 `node server.js`，打开 `http://127.0.0.1:8787`。板端部署与 ADB 转发见 [模型运行记录](qwen3-vl-board.md)。
2. 连接模型，选择 1–20 张 JPEG/PNG。每张不超过 4 MiB，总计不超过 20 MiB。问答使用第一张，压测按任务序号轮换，每个请求只有一张图片。
3. 进入“性能测试”，在“测试场景”选择下列模式。稳定性入口会默认选中长稳模式。
4. 配置业务复核问题和固定输出上限。开始测试后可查看实时统计，完成后在“测试报告”下载完整 JSON。

| 场景 | 负载方式 | 重点观察 |
| --- | --- | --- |
| 单请求基线 | 强制并发 1，按请求数或时长截止 | 多图片延迟基线，人工检查回答 |
| 多并发吞吐 | 独立 slot，请求结束后补发 | 分别运行 1、2、4 等并发，比较总吞吐和延迟 |
| 持续输入 | 按指定请求/秒产生任务，与请求完成速度无关 | 队列增长、拒绝、可持续完成吞吐 |
| 突发输入 | 按间隔批量提交任务 | 排队、峰值积压、停止输入后排空时间 |
| 高负载稳定性 | 固定并发持续补发 | 已验证配置的持续表现，最长 8 小时 / 100000 次 |

持续输入和突发模式也有 100000 次任务上限。队列容量 0–1000，满队列时立即拒绝并计数。到达时限后停止产生新任务，已排队任务继续处理；点击停止则取消排队任务，等待在途请求完成或超时。因此总运行时间可以超过最大发起时长。

当前为手动逐档对比，不会自动重启板端或改变模型上下文、session。填写的服务 session 数是操作者声明，不是设备自动检测；必须与实际 `--n-session` 一致。HTTP 并发不等于硬件并行度，当前已验证板端启动配置仍为单 session。

## 指标口径

- 请求吞吐：成功请求数 / 总墙钟时间，包含排空阶段。
- 输出吞吐：成功请求的真实 completion token 总数 / 总墙钟时间；服务缺少 token 数据时不估算。
- 首内容延迟：HTTP 发出到首次非空内容，不包含本地排队。
- 含排队 P50/P95/P99：计划到达至响应结束，包含本地调度、排队、网络及服务处理。
- 排队 P95：计划到达至 HTTP 发出。延迟分位数仅统计成功请求。
- 成功率：成功 / 已完成请求；另外显示成功 / 全部到达任务，避免队满拒绝被成功率掩盖。
- 到达、成功、失败、拒绝、取消、排队、在途分开显示。停止输入后的排空耗时包含剩余在途请求。

完整 JSON 含逐请求图片索引、排队和端到端耗时以及图片哈希。图片本体、密钥、生成回答不写入报告。该 Demo 测量性能与传输成功，业务复核准确率需要另外准备标注、保留推理回答并评测，不能由请求成功率推导。

## 验证边界

使用不同图片降低单图缓存偏差，但仍可能命中服务端缓存。当前未自动扫描最高负载，也不以内存 100% 作为通过条件。温度、内存和健康监控暂未整合进网页；可另开终端执行 `node scripts/sample-memory.mjs 1800` 保存独立内存采样。

自动化测试覆盖 slot 隔离、开放输入下的队列上限与拒绝、排空、取消排队、固定并发补发以及报告去除敏感内容。测试命令：`node --test`。

## 业务事件复核

页面提供打电话、吸烟、玩手机、未戴安全帽、未穿反光衣、人员闯入、跌倒、打架、烟火九个任务。选事件、填写目标位置或禁区条件，点击“应用到问答和压测”，提示词同步到两个入口。约定返回 event、verdict、evidence、limitation 四个 JSON 字段。

这是提示词约定，尚未做结构校验或自动判分。当前只发送单张图片：人员闯入缺少禁区范围应无法判断；倒地姿态不能证明跌倒过程；打架需要排除运动等相似动作。性能成功率与事件准确率独立。真实业务验收需要每类正例、反例、遮挡/模糊等困难样本及标注，再分别计算误报、漏报和无法判断比例。
