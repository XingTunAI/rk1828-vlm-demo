## 已验证的两套配置

| 项目 | 最新原生验证（2026-10-12） | 历史网页业务验证（2026-10-10～11） |
| --- | --- | --- |
| Runtime / 设备固件 | 1.1.0 / 1.1.0 | API 1.0.4 / 固件标识 1.0.401 |
| 模型 | Rockchip 官方 v1.1.0 Qwen3-VL-4B | Firefly 转换 Qwen3-VL-4B |
| 视觉输入 | 384×384 | 384×384 |
| 模型上下文上限 | 查询为 1024 | 模型为 32768，服务按各次测试另设 |
| 验证入口 | SDK 原生语言、视觉和图文工具 | RKLLM3 Server + 本项目 HTTP 控制服务 |
| 结果入口 | [1.1.0 扩样](sdk-1.1.0-samples.md) | [图片复核](image-review-test.md)及历史报告 |

新版原生工具已加载官方模型并完成推理。这不表示常驻 HTTP 服务已经完成同模型业务复测。模型文件名、上下文、图像标记、权重和 Runtime 必须按同一套配置核对。

## 部署阅读顺序

1. 按[设备接入](board-bringup.md)确认 ADB、Host、PCIe、RK1828 在线及服务状态。文中的 2026-10-10 状态表为旧快照。
2. 准备匹配版本的 Runtime、设备固件和模型包。安装包不包含全部模型权重；传输后校验六个核心文件。
3. 先用匹配 SDK 的原生示例完成单图推理；新版已验证的配置见[首轮复测报告](sdk-1.1.0-retest.md)。
4. 使用 HTTP Demo 时，再配置对应 RKLLM3 Server，检查 health、模型列表及真实图片请求，然后运行 `node server.js`。
5. 按[Demo 使用说明](capacity-demo.md)测试少量不同图片；成功后才进入[板端采样与负载测试](board-soak.md)。

现有 `scripts/start-qwen3-vl-board.sh` 使用 Firefly 模型文件名，默认上下文 768。其参数及文件清单见[旧版模型记录](qwen3-vl-board.md)。只修改模型目录并不能保证适配官方包；不要将旧测试中的 ctx16384 或 ctx32768 套到官方 max_ctx_len=1024 的模型上。

## 运行时升级记录

2026-10-12 使用 SDK 1.1.0 生成的 `rknn3_rk182x_m2_installer_arm64.tgz` 更新 Host Runtime 和配套设备固件，随后重启并确认两者均为 1.1.0。升级后官方模型初始化成功，详细结果见[复测报告](sdk-1.1.0-retest.md)。

安装前停止推理并备份 Runtime、固件文件及服务配置；将安装包解压到独立目录，检查该版本安装脚本再执行。安装脚本会清理其解压文件，应将原压缩包保存在目录外。具体安装检查见[设备接入](board-bringup.md#2-安装并检查运行时)。不要只凭安装脚本退出判断升级完成，应核对设备在线、运行版本和一次真实推理。

`rknn-smi` 自身版本与设备固件版本不是同一字段。本次 SMI 工具仍显示 1.3.0，不能据此认为设备没有升级。

## 网页运行位置

| 方式 | 控制服务位置 | 浏览器如何访问 |
| --- | --- | --- |
| PC 控制 | PC 上运行 `node server.js` | PC 访问本地 8787；通过 ADB 转发 18080 到板端模型 8080 |
| 板端控制 | 板端运行 `node server.js` | HDMI 浏览器访问板端本地 8787；PC 可将本地 8787 转发到板端 8787 |

两种方式的模型地址由控制服务所在机器访问。板端长测使用板端控制服务；PC 上已有 8787 服务时先确认端口归属，避免查看错任务。ADB 是端口转发，HDMI 页面由浏览器显示。详细命令见[旧版运行记录的连接部分](qwen3-vl-board.md#板端控制服务与-pc-查看)和[HDMI 指南](hdmi-demo.md)。
