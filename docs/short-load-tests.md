## 2026-10-11 两并发初测

运行 `147d2962-53db-4459-a2b5-f1c90575848a`，SDK 帮助确认 `--n-session` 支持多 session，模型实际启动为 2，两个 slot 分别接收请求。计划 90 秒，监控因连续 3 次采样失败提前停止输入，在途请求等待 120 秒超时收尾。

结果：3 请求，1 成功、2 超时。开始时设备 Online / OK，随后 rknn-smi 不可用；HTTP `/health` 仍返回 OK，说明仅检查 HTTP 存活不够。未取得有效高负载 NPU 样本，因此不报告满载吞吐。

人工恢复时模型服务停止超时，硬件复位并加载既有固件、恢复单 session 后设备重新 Online / OK。没有证据将根因确定为内存不足；需进一步排查 SDK / 固件 / 模型多 session 兼容性。不继续试 4 或 8 并发，避免反复触发同一故障。

各档均为短测，样本数有限，P95 可能接近样本最大值；无独立预热，包含启动阶段与排空耗时。图集配置为 20 张，但实际遍历张数随请求数量变化。输出吞吐包含输入处理及其他请求耗时，不等同于 decode TPS。提示词、输入输出预算与上下文不同，不能用本表直接比较同一复核业务的加速倍数。

本轮最高利用率来自 6570 个实际处理输入 token 的大输入档：均值 73.8%，最大 93%，14 个采样中 6 个达到 90%；最高温度 61℃，最小空闲加速器内存 827.60 MB，设备状态保持正常，无遥测失败。5 请求全部成功，端到端 P50 / P95 为 12.86 / 15.49 秒。服务端 prefill 速度约 539–566 token/秒，decode 约 33.3–35.7 token/秒；整体输出吞吐只有 2.08 token/秒，因为大部分时间在处理输入。以上指标口径不同，不应混用。

该档实际只遍历 5 张图片，输出上限 32 token；长输出档实际只遍历 4 张，每张生成 512 token。不能把它们当作全素材验证。没有达到持续 100% NPU 利用率；短时达到 93% 也不是满载长稳结论。多 session 异常需单独定位，不能用增加输入掩盖并发失败。

两并发的两次失败均约 120 秒超时；成功响应的延迟只有一个样本，不作为该档 P95 性能结论。温度也只有启动时有效采样，不能代表故障期间最高温度。

测试结束后已恢复单 session / 768 上下文，并完成恢复验证（运行 033faaec-0064-4efc-8f05-583ef7a3d242）：4/4 请求成功，设备 Online / OK。所有负载已结束，模型服务保留供 Demo 使用，旧长测提醒已停用。
