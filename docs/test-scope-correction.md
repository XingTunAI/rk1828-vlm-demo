## 优先增加图片任务

目标链路：视频 → YOLO 输出候选框和事件类别 → RK1828 复核 → 确认 / 否认 / 无法判断。

当前只评估1828，用图片、候选框和事件关键词模拟上游输出。固定短提示词，例如“判断框内人员是否打电话，只输出确认、否认或无法判断”。不要重复规则撑大输入；输出预算固定且足够容纳短结论。

1. 先补充不同人物、光照、遮挡和目标尺寸的图片及真实或人工审核的框。不要把未标注素材类别直接视为真值。
2. 同一事件使用相同短提示词，增加独立图片任务数量与送入频率，记录提交、完成、积压、丢弃和超时数量。扩大素材库与增加处理负载是两件事，不能仅凭图片数宣称负载增加。
3. 先用单session连续图片复核测稳定吞吐，再按实测能力设置到达率阶梯；多session需先解决此前故障。
4. 当前视觉输入固定384×384，上传更大的JPEG不等于增加视觉token。单次多图、高分辨率、连续帧支持均需核对SDK并验证，暂不宣称已实现。
5. 跌倒、打架等时序事件不能靠单张图确认完整过程；需另做连续帧方案。

核心指标为复核图片/秒、端到端P50/P95/P99、队列等待、超时/失败、真实标注准确性；同时记录NPU曲线、温度、内存、模型配置及实际输入输出token。NPU百分比是辅助资源指标，不作为业务通过条件。
